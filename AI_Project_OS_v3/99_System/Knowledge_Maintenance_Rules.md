# Knowledge Maintenance Rules

> 本文件规定 AI Project OS 中知识如何新增、更新、废弃和归档。目标不是保存所有聊天，而是保存真正具有长期价值的信息。

## 一、知识库不等于聊天记录

默认不保存完整聊天。聊天属于探索过程；知识库保存讨论之后沉淀出的结果。

优先保存：背景、核心判断、决策、方法论、项目状态、待解决问题、关键数据、下一步动作。

## 二、什么内容值得进入 GitHub

满足以下任一条件，可以考虑沉淀：

1. 形成新的业务判断 → 进入 Decision Log
2. 原有判断发生变化 → 记录原判断、新证据、新判断、修改原因
3. 项目进入新阶段 → 更新 Current Status
4. 得到可复用的方法 → 进入 Methodology / Knowledge Base
5. 得到影响决策的关键业务数据 → 更新项目状态或 Decision Log
6. 形成正式输出物 → 作为项目资产留存

## 三、哪些内容默认不进入 GitHub

一般不保存：
- 临时灵感
- 未验证猜想
- 单次措辞修改
- 普通聊天
- 已被快速推翻的方案
- 没有长期价值的执行细节

如果具有潜在价值但尚未确认，进入 Draft / Inbox，而不是正式知识库。

## 四、知识状态

建议知识分为：
- Draft：探索中
- Active：当前有效，AI应优先使用
- Superseded：已被新结论替代，但保留历史
- Archived：项目结束或长期不再使用

## 五、禁止直接删除重要历史判断

如果一个结论发生变化，不删除旧版本，而应记录 Decision Evolution：原判断、变化时间、变化原因、新判断。

## 六、项目文件结构

每个重要项目建议至少包含：
- README.md：项目是什么、为什么存在
- Current_Status.md：当前阶段、当前问题、下一步
- Decision_Log.md：核心判断、重大变化
- Methodology.md：如果项目形成独立方法论则保留
- Archive/：历史方案、已废弃版本

## 七、项目状态更新规则

Current_Status 不保存完整历史，只回答“现在是什么状态”。推荐结构：当前阶段、已完成、当前判断、关键数据、当前问题、下一步。

历史变化进入 Decision Log 或 Archive。

## 八、Decision Log 记录标准

一个值得记录的 Decision 至少包含：
- 日期
- 背景
- 问题
- 判断
- 原因
- 影响
- 状态（Active / Superseded）

## 九、方法论提炼规则

如果同一种问题至少出现两到三次，应判断是否可以从项目经验提升为可复用方法。

例如物业类型、亮点字段标准、图片标准中反复出现“定义 → 生产 → 验证 → 表达”，则可沉淀为信息标准建设方法论。

## 十、聊天结束后的沉淀流程

重要讨论结束后，AI判断本次是否产生知识资产。

如果有：
- 是否改变项目状态？→ 更新 Current_Status
- 是否产生重要判断？→ 更新 Decision_Log
- 是否产生通用方法？→ 更新 Methodology
- 是否有正式产出？→ 存入项目目录

## 十一、GitHub提交原则

一个 Commit 尽量只做一类变化。

推荐示例：
- `docs: 更新空间化项目状态`
- `decision: 新增门店信息层级判断`
- `methodology: 补充信息质量评估方法`
- `archive: 归档旧版物业类型规则`

## 十二、更新频率

不要求每天强制更新。

- 重大决策：实时更新
- 项目状态：阶段更新，例如方案确认、功能上线、数据复盘
- 整体项目：每周/双周复盘哪些决策变化、哪些项目长期没更新、哪些方法值得沉淀

## 十三、AI与GitHub的协作原则

默认模式：聊天 → 形成结论 → AI提出建议沉淀内容 → 用户确认 → AI更新 GitHub。

如果用户直接说“把今天的结论更新到知识库”，AI需要：
1. 读取已有文件
2. 判断应该更新哪个位置
3. 保留历史关系
4. 再进行修改

禁止没有读取当前版本就直接覆盖。

## 十四、敏感内容规则

工作知识库可能包含公司内部数据、业务策略、未公开规划。因此正式进入长期使用后，建议 GitHub Repository 设置为 Private。

避免写入：
- 密码
- API Key
- 用户隐私信息
- 内部账号
- 未脱敏敏感数据

## 十五、长期目标

AI Project OS 不追求保存最多内容，而追求：**让最重要的认知不会丢失。**

最终知识库应该能够回答：
- 我正在做什么
- 为什么这么做
- 我以前是怎么判断的
- 哪些判断已经改变
- 下一步该做什么
- 我逐渐形成了哪些自己的方法
