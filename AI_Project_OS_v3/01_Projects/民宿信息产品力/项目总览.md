# 民宿信息产品力项目总览

## 项目定位

民宿信息产品力建设，核心目标是：

通过建立适合民宿行业特点的信息体系，提升住宿商品表达能力，帮助用户更准确理解房源价值，同时提升平台供给质量和业务增长能力。

信息不是简单的信息采集，而是连接：

供给理解 → 商品表达 → 用户决策 → 业务增长

的基础能力。

## 一、业务背景

### 民宿行业特点

相比酒店行业，民宿具有明显的非标准化特点：
- 房源形态差异大
- 空间体验价值突出
- 同类商品难以简单比较
- 用户决策依赖更多场景化信息

例如，同样是“三居”，可能存在独栋别墅、山景小院、亲子空间、多卧套房、客栈房型。

用户关注的不只是基础设施，而是“这个住宿适不适合我的出行场景”。

因此，传统酒店式的信息结构无法完全满足民宿表达需求。

## 二、核心问题

### 1. 信息标准不足

大量信息依赖房东自由填写，导致定义不统一、信息质量不稳定、用户理解成本高。

例如别墅、客栈、公寓缺少统一分类标准。

### 2. 信息结构无法充分表达民宿价值

当前更多围绕“有什么”进行描述，但用户实际决策关注“为什么值得选择”。

例如不仅需要知道“有泳池”，还需要知道是否私享、无边、山景、恒温等。

### 3. 用户端表达与商家端采集脱节

过去信息建设更多关注商家填写什么。

未来需要转变为：用户需要什么信息 → 平台定义标准 → 商家完成采集 → 用户侧表达。

## 三、核心建设方向

### 方向一：基础信息体系建设

目标：建立民宿通用基础信息标准。

包括房源基础属性、设施信息、规则信息。

核心价值：降低用户决策成本，提高信息可信度。

### 方向二：空间信息体系建设

核心判断：民宿价值很大程度来源于空间体验。

因此需要从“房间数量”升级到“空间结构”。

例如多居房源不仅需要知道3间卧室，还需要知道每间卧室是否独立、是否有独立卫生间、客厅厨房公区关系、是否适合多人同行。

空间化是民宿区别于酒店的重要信息能力。

### 方向三：特色亮点信息体系建设

目标：挖掘民宿差异化价值。

重点方向：景观、泳池、小院花园。

建设方式不是无限增加标签，而是：基础属性采集 → 前端组合包装 → 用户场景表达。

### 方向四：品类和结构体系建设

民宿不能简单复制酒店分类体系，需要建立适合民宿特点的分类方式。

#### 物业类型
短期建立可落地、高准确率打标规则；长期形成民宿分类体系。

#### 门店与房型结构
随着门店聚合发展，信息结构需要从房源维度升级为门店 + 房型 + 房源三层结构。

核心原则：先识别门店特征，再建立门店信息，再关联房源，而不是先有房源再强行聚合。

## 四、核心方法论

### 用户需求驱动
不是“平台有什么信息”，而是“用户在什么决策场景需要什么信息”。

### 信息分层建设
第一层事实信息：回答“是什么”。
第二层空间信息：回答“怎么使用”。
第三层体验信息：回答“为什么值得选择”。
第四层用户标签：回答“适合谁”。

## 五、当前重点项目

截至2026年Q3：

1. 多居空间化：提升多居房源的信息表达能力。
2. 门店信息结构升级：建立门店信息 + 房型信息的新货架结构。
3. 物业类型体系：支持聚合和用户理解。
4. 特色亮点体系：一期聚焦景观、泳池、小院花园。
5. 图片信息体系：建立图片分类 → 图片质量 → 用户表达完整体系。

## 六、长期愿景

打造民宿平台的信息基础设施。

让平台能够理解不同类型民宿价值，用结构化信息表达差异，帮助用户找到真正适合自己的住宿。

最终形成：**民宿商品理解能力。**
